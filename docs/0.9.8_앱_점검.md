# 0.9.8 앱 점검

## 이번 수정

- 미리보기와 인쇄용 문서 준비를 별도 경로로 분리했다. 화면용 데이터는 인쇄에 재사용하지 않는다.
- 사진 미리보기는 작은 비트맵으로 읽되, 원본의 가로·세로 크기를 기준으로 배치한다. 원본 크기, 회전, 여백, 잘림 위치는 유지한다.
- PDF 배치와 모아찍기 미리보기는 화면용 해상도를 사용한다. 실제 인쇄는 사용자가 선택한 DPI와 압축 설정을 유지한다.
- 긴 PDF의 미리보기는 너비와 높이를 모두 제한한다.
- 내용 회전은 큰 비트맵을 추가로 복사하지 않고 그리는 좌표를 변환한다.
- 중복 미리보기 요청은 이전 생성을 취소한다. 파일·프린터·설정이 바뀌면 이전 결과를 표시하지 않는다.
- 미리보기 생성과 인쇄 준비가 동시에 큰 이미지를 읽지 않도록 처리 순서를 조정했다.
- PDF 페이지를 그리다 오류가 나거나 취소돼도 페이지를 종료하도록 정리했다.

## 별도 수정이 필요한 항목

아래는 0.9.8 점검 당시 남아 있던 항목이다. 기존 기록은 유지하고, 0.9.9에서 바꾼 내용을 각 항목 아래에 덧붙였다. 전체 수정 내역은 [0.9.9 수정 내역](0.9.9_수정내역.md)에 정리했다.

### 1. 큰 파일을 IPP 패킷에 넣을 때 메모리 복사가 반복됨

IppClient의 Print-Job·Send-Document는 문서를 여러 ByteArrayOutputStream에 복사한다. 원본을 그대로 보내는 작업도 파일 크기보다 훨씬 많은 메모리를 사용할 수 있다. IPP 헤더와 문서를 나누어 순차 전송하도록 바꾸는 것이 필요하다. Digest 인증의 본문 해시 처리도 함께 확인해야 한다. 이번 패치에서는 전송 패킷 구현을 바꾸지 않았다.

0.9.9 처리: 문서를 캐시 파일로 준비하고, 작은 IPP 헤더와 파일 스트림을 순서대로 전송하도록 바꿨다. Digest auth-int 해시도 같은 바이트 순서를 스트림으로 읽어 계산한다. 인증 재시도에서는 새 스트림을 열고, 문서 길이가 바뀌거나 파일을 읽지 못하면 실패한다.

### 2. 컬러 문서가 흑백 PCL 경로로 선택될 수 있음

변환 형식 선택은 컬러 요청을 고려하지 않고 PCL을 PNG·JPEG보다 먼저 선택한다. 현재 PCL 인코더는 흑백 래스터이므로, PCL과 JPEG 등을 함께 광고하는 프린터에서 컬러를 요청해도 흑백 변환될 수 있다. 명시적 컬러 요청에는 흑백 전용 경로를 제외하거나 이유를 안내해야 한다. 이번 패치에서는 형식 선택 정책을 바꾸지 않았다.

0.9.9 처리: 컬러·자동 컬러 요청에서는 앱의 흑백 PCL 변환을 후보에서 제외한다. 컬러를 유지할 다른 변환 형식이 없으면 전송하지 않고 이유를 안내한다. 프린터가 지원하는 PCL 원본 파일의 전송은 기존처럼 유지한다.

### 3. 비중립 프린터 기본값과 앱 배치가 겹칠 가능성

앱에서 모아찍기·회전을 적용한 후, 프린터가 1-up·세로·배율 없음 등의 중립값을 광고하지 않으면 해당 IPP 옵션을 생략한다. 이때 프린터 기본값이 모아찍기나 가로 방향이면 이미 배치한 문서에 다시 적용될 가능성이 있다. 광고 정보가 부족한 경우와 실제 미지원을 구분하는 검증이 필요하다. 실제 장치로 이 조건을 재현한 것은 아니다.

0.9.9 처리: 앱 배치와 충돌하는 프린터 기본값이 확인되고 이를 해제할 중립값을 사용할 수 없으면, 전송 전에 이유를 안내한다. 지원 목록이 없더라도 기본값이 중립값으로 확인되면 이를 사용한다. 단순히 광고 정보가 없다는 이유만으로 충돌한다고 단정하지는 않는다.

## 기존 제한

입력 파일과 생성된 출력 문서에는 각각 50 MiB 제한이 남아 있다. 높은 DPI·무손실 PostScript는 이 제한을 넘을 수 있다. 품질을 자동으로 낮추지는 않고 실패 이유를 안내한다. 한도만 늘리기보다는 전송 버퍼와 변환 출력 누적 방식을 먼저 개선할 필요가 있다.

사진의 실제 인쇄용 변환은 원본 해상도를 읽는 방식을 유지한다. 따라서 화면 미리보기가 성공해도, 원본 전송이 아닌 변환 인쇄에서 큰 사진이나 높은 선택 DPI가 메모리 한계에 걸릴 수 있다. 이번 수정은 미리보기 때문에 인쇄 품질을 낮추거나 작은 화면을 위해 원본 전체를 읽는 문제를 분리한 것이며, 인쇄용 대용량 처리를 전부 해결한 것은 아니다.

0.9.9 처리: 입력·출력의 고정 50 MiB 제한을 제거했다. 사진은 가능한 형식에서 원본을 타일 단위로 읽고, PDF 배치·모아찍기와 프린터 언어 변환은 띠 단위로 처리한다. 출력은 파일로 저장해 스트림으로 전송하며 선택 DPI·PostScript 품질을 자동으로 낮추지 않는다. 다만 실제 저장 공간·메모리·프린터 한계는 남아 있다. TXT 변환의 전체 텍스트·페이지 보유, 최종 JPEG·PNG 출력의 전체 페이지 비트맵, 영역 읽기를 지원하지 않는 이미지 형식도 별도 제약이다.

## 확인 범위

단위 테스트 104개와 Android 빌드가 통과했다. 크기 계산, 배치, 설정 불변성을 포함한다. 실제 사진의 화면 표시와 프린터 출력 결과는 별도 확인 대상이다. 이번 점검에서 실제 프린터로 인쇄 요청을 보내지는 않았다.
