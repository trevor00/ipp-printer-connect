# 0.9.9 수정 내역

0.9.8 점검에서 남겨둔 전송 중 메모리 복사, 컬러 문서의 흑백 변환, 앱과 프린터의 중복 배치 문제를 수정했다. 큰 사진과 PDF의 인쇄용 변환도 파일·부분 처리 방식으로 바꿨다.

## 문서를 파일로 준비하고 스트림으로 전송

선택한 문서는 앱의 임시 파일로 복사한다. 프린터가 원본 형식을 지원하고 앱 배치가 필요하지 않으면 이 파일을 그대로 읽어 전송한다. 변환이 필요한 경우에도 결과를 메모리의 큰 바이트 배열에 쌓지 않고 파일에 저장한다.

Print-Job·Send-Document는 작은 IPP 헤더를 먼저 보내고 문서 파일을 이어서 읽는다. 전체 문서를 포함한 패킷 배열을 여러 번 만드는 처리를 없앴다. HTTP Content-Length에는 헤더와 문서의 실제 길이를 사용한다.

Digest auth-int 인증은 전송할 바이트와 같은 순서로 스트림을 읽어 해시를 계산한다. 인증 재시도 때도 파일을 다시 열어 같은 본문을 보낸다. 문서가 짧아지거나 길어졌거나, 파일을 열거나 읽지 못하면 실패 이유를 표시한다. 명시적인 인증 응답이 아닌 일반 통신 오류 때문에 인쇄 요청을 자동으로 다시 보내지는 않는다.

입력 파일과 변환 결과에 걸려 있던 고정 50 MiB 제한은 제거했다. 한도를 숫자만 늘린 것이 아니라, 원본 준비·변환 결과 저장·IPP 전송을 파일과 스트림으로 연결했다.

## 큰 사진과 PDF의 인쇄용 처리

사진은 이미지 형식이 영역 읽기를 지원하면 원본을 작은 타일로 나누어 읽는다. EXIF 방향과 사용자가 정한 배치는 좌표에 반영한다. 큰 원본 비트맵과 회전한 비트맵을 통째로 동시에 만들지 않는다.

PDF 배치와 모아찍기는 페이지를 작은 가로 띠로 나누어 그린다. PostScript·PWG Raster·URF·PCL 출력도 띠별로 그린 데이터를 순서대로 저장한다. 긴 문서 전체나 높은 DPI의 한 페이지를 모두 픽셀 배열로 유지하던 부담을 줄였다.

이 과정에서 실제 인쇄의 선택 DPI와 PostScript 이미지 품질은 바꾸지 않는다. JPEG 품질 90·100과 무손실 RGB 중 사용자가 선택한 방식을 유지한다. 메모리 때문에 낮은 DPI나 낮은 품질로 몰래 바꾸는 처리는 넣지 않았다.

미리보기는 계속 화면용 크기로 따로 만든다. 미리보기에 사용한 축소 이미지를 실제 전송 문서에 재사용하지 않는다.

## 컬러 요청과 PCL 변환

현재 앱의 PCL 변환은 흑백 전용이다. 컬러 또는 자동 컬러를 요청한 경우에는 이 경로를 선택하지 않고, PDF·PostScript·PWG Raster·URF·PNG·JPEG 등 프린터가 광고한 다른 형식을 찾는다.

컬러를 유지할 변환 형식이 없으면 흑백으로 바꾸어 보내지 않고 전송 실패 이유를 안내한다. 이 제한은 앱이 새로 만드는 흑백 PCL에만 적용한다. 원본 PCL·PCL XL에는 컬러 정보가 포함될 수 있으므로, 프린터가 원본 형식을 지원하면 기존처럼 그대로 전송할 수 있다.

PCL 출력의 용지·가로세로·여백·커서와 래스터 방향도 명시하도록 수정했다. 이전에는 세로 방향만 지정하고 용지 등의 기본값을 프린터에 맡겨 가로 문서의 배치가 달라질 수 있었다. A3·A4·A5·Letter·Legal·Ledger·Executive를 구분하며, 이외의 사용자 지정 크기를 임의로 Letter나 가까운 용지로 바꾸지 않는다. 설정할 수 없는 크기는 이유를 안내한다. 이 명령으로 프린터의 물리적 출력 불가 영역을 없앨 수는 없다.

용지 코드와 명령 순서는 [HP PCL 5 Quick Reference](https://h10032.www1.hp.com/ctg/Manual/bpl13205.pdf)와 [PCL 5 Reference](https://www.hp.com/ctg/Manual/bpl13210.pdf)를 기준으로 했다. 실제 기기의 원점·출력 가능 영역은 기종별 확인이 필요하다.

## 프린터가 배치를 다시 적용하는 경우

앱에서 페이지 선택·모아찍기·회전 등을 끝낸 문서는 프린터가 같은 배치를 한 번 더 적용하면 안 된다. 프린터가 광고한 1쪽씩·세로·배율 없음·가운데 같은 중립값을 사용하도록 확인한다.

프린터 기본값이 앱 배치를 다시 바꾸는 것으로 확인됐는데 이를 해제할 중립값을 사용할 수 없으면, 전송 전에 실패 이유를 표시한다. 지원 목록이 비어 있어도 기본값이 중립값으로 확인되면 이를 사용한다. 광고가 없다는 이유만으로 문제가 있다고 판단하지는 않는다.

## 임시 파일 정리

문서 준비 과정의 임시 파일은 작업별로 관리한다. 전송에 필요한 결과 파일 하나만 넘기고 나머지는 정리한다. 결과 파일도 전송 성공·실패·인증 요청 반환·예외 발생 뒤 닫는다.

미리보기 파일은 미리보기 세션이 소유한다. 생성 실패, 이전 요청 취소, 문서·설정 변경으로 결과를 버리는 경우와 창을 닫는 경우에도 정리한다. 사용자가 선택한 원본 파일을 수정하거나 삭제하지 않는다.

## 남아 있는 제약

고정 파일 크기 제한을 없애도 휴대폰 저장 공간, Android의 메모리, 프린터가 처리할 수 있는 문서 크기와 형식에는 한계가 있다.

- TXT를 변환할 때는 전체 텍스트를 문자열로 읽고 페이지를 구성한다. 아주 큰 TXT는 메모리를 많이 사용할 수 있다.
- 최종 전송 형식이 JPEG·PNG이면 이미지 압축 과정에 전체 페이지 비트맵이 필요하다. 이 경로까지 완전히 띠 단위로 바뀐 것은 아니다. 여러 페이지를 이미지 한 파일로 합쳐 보내지도 않는다.
- 영역 읽기를 지원하지 않는 이미지 형식은 원본 전체를 읽어야 할 수 있다. 메모리가 부족하면 자동 축소하지 않고 실패 이유를 안내한다.
- 저장 공간 부족이나 프린터의 용량·형식 제한으로 인쇄가 실패할 수 있다. 앱의 작업 접수 성공만으로 실제 종이 출력을 보장하지는 않는다.

따라서 이번 수정은 큰 문서 처리 시 불필요한 복사와 전체 페이지 메모리 사용을 줄인 것이며, 모든 크기·형식의 문서가 항상 출력된다는 의미는 아니다.
