# 0.9.14 수정 내역

작성일: 2026-10-21
버전: 0.9.14 / versionCode 104

## 변경 기준

흑백 기본값은 유지한다. 원본 전송에서는 문서 바이트를 바꾸지 않고 사용자가 선택한 IPP 옵션을 보낸다. 앱 변환이 필요한 경우 출력 형식과 필요한 해상도·압축을 화면에서 선택한다. 부족한 메모리나 지원하지 않는 조합 때문에 임의로 품질을 낮추거나 다른 형식으로 재전송하지 않는다.

미리보기와 인쇄는 서로 다른 파일 준비 경로다. 화면용 축소는 미리보기에만 사용하며 출력에 재사용하지 않는다. 원본을 직접 보내는 경우의 미리보기는 내용 확인용이지 프린터가 처리한 최종 용지 배치를 보증하는 화면이 아니다.

## 점검 항목별 수정

| 기존 점검 | 수정 내용 |
|---|---|
| PDF 페이지 범위 선택이 전체 배치 변경으로 처리됨 | 내용 배치와 페이지 선택을 분리했다. 범위만 지정하면 원래 페이지 객체·크기·회전을 유지하여 선택한다. 앱에서 적용한 범위를 IPP로 중복 적용하지 않는다. |
| PDF 배치·모아찍기의 이미지화 | PdfBox-Android로 원래 콘텐츠 스트림·글꼴·이미지 리소스를 가져와 배치한다. PDF→PDF에 래스터 DPI를 요구하지 않는다. 페이지를 새로 배치하면 전자서명 등 원본 파일 동일성이 유지되는 것은 아니다. |
| 변환 시 IPP 맞춤·위치가 사라짐 | 실제로 문서에 배치를 적용한 경우에만 해당 IPP 옵션을 중립화한다. PDF 형식 변환만 수행했으면 IPP 배치 설정을 무조건 제거하지 않는다. |
| 두 곳의 배치 설정이 충돌함 | 앱에서 배치할 수 있는 문서는 페이지 배치 조작만 표시한다. 먼저 선택한 IPP 맞춤·위치는 보이는 페이지 배치로 옮기고 안내한다. |
| PostScript 별칭에서 숨은 JPEG 압축 | 화면과 저장 값에 정규화된 MIME을 사용한다. 형식 변경 시 압축 목록을 다시 만들고 표시와 실제 값을 맞춘다. PostScript 기본값은 무손실 RGB다. |
| 용지·여백 추정 | 매체별 media-col 정보와 표준 용지 이름의 크기를 읽는다. 정보가 없으면 A4나 5mm로 대체하지 않는다. 비대칭 광고 여백을 네 변에 각각 적용한다. 변환에 필요한 크기·영역을 알 수 없으면 이유를 안내한다. |
| 설정 대체를 일반 성공으로 표시 | Validate-Job에도 설정 엄수 속성을 보내고 경고·미지원 속성을 검사한다. 사전 검사 경고는 전송 전에 중단하고, 접수 후 경고는 접수 사실과 구분하여 표시한다. |
| 잘린 IPP 응답 | 속성 그룹·컬렉션·길이·종료 구분자·요청 번호를 검사한다. HTTP 응답은 4MiB까지 읽는다. 전송 후 응답을 확정할 수 없으면 접수 여부 확인 불가로 표시한다. |
| 미리보기의 색상 차이 | 흑백 선택과 PCL의 1비트 흑백 변화를 화면에 반영한다. 프린터의 색상 관리와 JPEG 압축 결과까지 완전히 재현하는 것은 아니므로 참고용이라고 표시한다. |
| Raster 세부 조건 누락 | PWG 해상도·색상 유형·뒷면 처리와 URF 지원 토큰을 조회한다. 현재 인코더와 맞지 않는 조합은 다른 설정을 선택하도록 안내한다. PWG 헤더의 전체 페이지 수·양면·선택 품질도 실제 작업 값에 맞춘다. |
| 변환의 보존 범위 불명확 | 픽셀화, 8비트 RGB, 투명 부분의 흰색 합성, 색상 프로파일·HDR 손실, TXT의 글꼴·줄바꿈 규칙을 변환 안내에 명시했다. 다중 프레임을 첫 프레임 하나로 조용히 바꾸지 않고 변환을 중단한다. |
| 작업 중단과 중복 출력 위험 | 준비 중 취소를 제공한다. 전송 중 문제가 생기면 자동 재전송하지 않는다. 이미 문서를 보낸 뒤 통신 예외가 생긴 경우 자동 취소를 보내 접수된 작업을 바꾸지 않는다. 앱 재실행 시 이전 준비 중단 또는 전송 결과 불확실성을 알린다. |
| 잘못된 입력·복원 | 잘못된 매수를 1부로 대신 보내지 않는다. 파일 형식 확인 완료 전 인쇄를 막고 준비 시 다시 확인한다. 동적 선택 목록은 인덱스 대신 MIME·DPI·압축 등 실제 값을 기준으로 복원한다. |

## 메모리·임시 파일

- PDF 래스터 작성기의 객체 위치·페이지·리소스·명령 인덱스를 임시 파일로 옮겼다.
- PDF 편집 라이브러리의 스트림 저장은 디스크 기반으로 설정했다. 그렇더라도 페이지 객체 등 모든 라이브러리 메모리 사용이 일정해지는 것은 아니다.
- 작업용 캐시 폴더를 분리하고 다음 프로세스 시작 시 이전 작업의 잔여 파일을 정리한다. 사용자 원본은 삭제하지 않는다.
- 기존 사진 타일 처리, 렌더링 띠 처리, TXT 페이지 처리, 순차 파일 전송은 유지한다.
- 영역 디코딩이 안 되는 사진, 아주 넓은 페이지, 복잡한 PDF 등은 여전히 메모리 한계가 있다. 부족하면 안내하며 원본·DPI·압축 품질을 자동 변경하지 않는다.

## 명시적으로 지원하지 않는 조합

- 주석·입력란이 있는 PDF의 배치 변경·모아찍기. 주석을 제외하고 보내는 대신 중단한다. 페이지 선택만 하는 경로는 별도로 보존 처리한다.
- UserUnit이 1이 아닌 특수 PDF의 배치 변경.
- 다중 프레임 GIF/APNG/WebP, 확인된 HEIF/AVIF 시퀀스의 앱 변환. 원본 형식을 프린터에 직접 보내는 경우는 프린터가 처리한다.
- URF 양면, PWG의 normal 이외 뒷면 처리, 지원 광고와 맞지 않는 Raster 해상도·색상 조합.
- 무제한 백그라운드 작업 유지. 준비·전송이 끝날 때까지 앱을 열어 두는 방식이며, 프로세스 종료 후 자동 재전송하지 않는다.

이 제한들은 내용을 임의로 바꿔 성공처럼 처리하는 대신, 현재 인코더가 보장할 수 없는 요청을 명확히 중단하기 위한 것이다. PDF나 사진을 모든 프린터에 항상 출력할 수 있다는 뜻은 아니다.

## 확인 범위와 1.0 판단

APK 빌드 및 단위·Android 검사 코드 컴파일을 완료했다. `:app:assembleDebug :app:compileDebugUnitTestKotlin :app:compileDebugAndroidTestKotlin` 결과는 BUILD SUCCESSFUL이다. APK 메타데이터도 0.9.14 / 104로 확인했다. `git diff --check` 오류는 없었다. 기존 Android API 사용 중단 예고 등의 컴파일 경고는 남아 있다.

사용자가 테스트를 맡기로 했으므로 검사 실행, 휴대폰 조작·설치, 프린터 전송은 하지 않았다. 기존 검사 통과 기록을 이번 버전의 결과로 사용하지 않는다. 생성 APK는 `app/build/outputs/apk/debug/app-debug.apk`다.

1.0 확정 전에는 아래를 사용자 환경에서 확인해야 한다.

1. 지원 형식 원본 전송과 미지원 형식 변환을 각각 출력한다.
2. PDF 페이지 범위만 선택했을 때 원래 크기·배치가 유지되는지 확인한다. 이어 배치 변경·모아찍기·회전을 확인한다.
3. PostScript 무손실/JPEG 선택과 화면 재생성 후 MIME·DPI·압축 복원을 확인한다.
4. 비대칭 여백과 출력 가능 영역 맞춤, 큰 사진·긴 TXT의 준비 및 취소를 확인한다.
5. 연결 중단 뒤 접수 여부 확인 불가 안내와 중복 자동 전송이 없는지 확인한다.
6. 실제 기기의 PWG/URF 지원 광고와 출력, 앱 재실행 시 작업 안내를 확인한다.

코드 수정과 컴파일 완료만으로 모든 프린터에서의 실사용 검증이 끝난 것은 아니다. 0.9.14로 먼저 확인하고 1.0 여부를 결정한다.
